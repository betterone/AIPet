# 猫的生命感：行为、动作与互动方案（2026-09-29）

## 结论

优先做一只猫在一个房间里的可信行为闭环：**察觉刺激 → 评估 → 用身体表达决定 → 移动或不移动 → 完成动作 → 恢复**。玩家提供机会，猫按自己的需要、经验和安全感回应。先验证这套闭环，再扩展九只猫的外观和动作量。

建议采用“语义行为规划 + 手工制作的四足动画 + 接触点修正”的方案。当前灰虎斑可用作行为原型；是否作为最终角色，取决于跑、扑、跳、舔毛和近景表情的动画试片。单纯提高移动速度或增加随机摆头，不能解决猫像在执行点击命令的问题。

## 现状与原因

| 现状 | 造成的体验 |
| --- | --- |
| `Simulation.Call(point)` 对所有未睡着的猫直接 `Go(Greet, point)`；地板轻点和“叫它过来”按钮都会调用它。`Pet()` 在非睡眠时也会 `Go(Greet, ...)`。 | 玩家一点，猫就服从目标坐标。性格、兴趣、亲疏和当下动作都不参与决定。 |
| 核心世界只有地面 `Point(x,z)` 和 `Walk` 一种移动状态；`Play` 到达目标后播 `Paw`，`Greet` 映射成 `Sit`。 | 没有短跑、追逐、伏低、扑击、上跳、落地，也没有空间高度。 |
| 导入灰虎斑是 27 骨、8 段本地制作的原型动作：Idle、Walk、Sit、Sleep、Eat、Paw、Groom、Stretch。`ImportedCatView` 用 Legacy `Animation` 手动按位移混合 Walk；移动表现用 `SmoothDamp` 且限速 1.45。 | 基础走路比旧版连续，但动作词汇和速度范围很窄。任何活动中的位移都混成同一段走路。 |
| 游戏时间为现实的 6 倍，核心模拟每 5 游戏秒更新一次，表现层预测路径中间位置。 | 新增“观察、犹豫、扑、落地”必须按屏幕上的真实秒数编排，不能直接沿用模拟秒数，否则观感会过快。 |
| 食物会自动补充，猫会自主去固定食盆；没有玩家“放食物／零食”的事件。 | 目前无法做“被食物吸引，确认安全后靠近”的交互。 |
| 当前房间寻路和可走区域是平面；角色眼睑、口部形变和真正的舔毛接触尚缺。 | 上蹿下跳需要可达的高处、起跳和落脚点，近景表情也还不能承受长时间特写。 |

对应代码：`Assets/Momo/Core/Simulation.cs`、`Assets/Momo/Core/WorldState.cs`、`Assets/Momo/Runtime/MomoApp.cs`、`Assets/Momo/Runtime/MomoHud.cs`、`Assets/Momo/Runtime/ImportedCatView.cs`、`Assets/Momo/Runtime/PetPresentationPath.cs`；现有资源边界见 `docs/IMPORTED-CAT.md`。

## 行为依据与产品原则

- 幼猫的物体游戏包含潜伏、追逐、拍打和扑击；社交游戏和物体游戏的高峰时段不同。把“幼猫更活跃”做成**活动发起频率、活动时长和恢复节奏**的差异，不是全天高速跑动。[Merck Veterinary Manual：猫的社会行为](https://www.merckvetmanual.com/behavior/behavior-of-cats/social-behavior-of-cats)
- 猫需要玩耍、攀爬、躲避、休息和安全的高处；可选择的环境本身是行为的一部分。[FelineVMA：猫的环境需求](https://catvets.com/wp-content/uploads/2026/02/FelineVMA-Environmental-Needs_2026-BW.pdf)
- 对人的靠近和接触受个体差异、经历及当时的情绪影响。让猫能观察、拒绝、后退或自己靠近；不要把“警戒”做成每次投喂都一样的固定演出。[AAFP/ISFM 猫友好互动指南](https://catvets.com/resource/aafp-isfm-cat-friendly-veterinary-interaction-guidelines/)；[Merck Veterinary Manual：猫的社会行为](https://www.merckvetmanual.com/behavior/behavior-of-cats/social-behavior-of-cats)
- 这里的动作频率、距离、时长和概率都应作为**产品调参假设**，用视频观察与真人体验修订；不能当作兽医文献给出的常数。

当前 `WorldState` 记录品种和性格，没有年龄／生命阶段。首个试片可以明确设定为“活跃的幼年猫”，再用同一动作集验证一只较稳重的成年猫；不要由品种名称猜年龄，也不要把所有猫调成同样的活跃度。首版无需加入自动长大，先把生命阶段作为清晰的角色配置。

## 玩家互动：从命令变成邀请

| 玩家操作 | 猫收到的刺激 | 允许出现的结果 |
| --- | --- | --- |
| 轻点空地 | 无移动命令；只处理点到的物件或镜头关注。 | 猫继续当前活动。取消“点击哪里就走到哪里”。 |
| 轻声唤它 | 听觉／社交刺激，无目标坐标。 | 耳朵朝向、转头、观察、短声回应、继续做事，或在愿意亲近且安全时自行靠近；可只走一段停下。 |
| 放下熟悉食物／少量零食 | 食物气味、位置和新异程度。 | 饿且放松时较快接近；生疏或受惊时先从安全处观察、慢慢靠近、停下嗅闻；不饿也可能忽略。食物要放在可到达、不会穿过家具的位置。 |
| 拖动逗猫棒／滚球 | 运动目标，可能触发捕猎式游戏。 | 注视 → 伏低 → 潜行／短追 → 扑击／拍打 → 停顿或继续；低能量、困倦或重复过多时可不追。 |
| 触碰猫 | 仅在猫确实近到能接触、没有躲避或睡熟时算抚摸。 | 接受、侧身蹭、短暂停留或走开。远处点击猫只触发注意，不隔空“摸到它”。 |

**喂食的一次完整片段**（熟悉食物、轻微谨慎时）：玩家放食物 → 耳朵和视线先定位 → 抬头观察人和周围 → 自己选择路径、接近到一段距离 → 暂停并嗅闻 → 再走到食物前 → 低头进食 → 抬头、舔嘴或离开。若是熟悉的饭点，可跳过长时间观察；若安全感低，可停在远处甚至返回藏身处。首版原型可把“定位／观察／嗅闻”各做成可中断的短段，再依据实际观感调时间。食物本身仍应由基础照料系统保障，玩家离开不应使宠物挨饿。

关系成长不应等于“服从率趋近 100%”。更熟悉的猫可以更快消除对人的戒备、更容易发起互动，但仍保留睡觉、独处和拒绝的空间。UI 应反馈“它听见了，在看你”或“它现在想休息”等**实际状态**，不预告一定会过来。互动进度记录“试过邀请”，而不是“成功召唤”。

## 系统设计

1. **行为层**：将当前 `Activity.Walk` 从“行为意图”中拆开。持久化猫的当前目标／活动（休息、觅食、探索、社交、游戏）、需要和个体倾向；短时的注意对象、谨慎程度、兴趣、熟悉度、接近意愿由确定性规则计算。安全和休息具有优先级；切换加入滞后、最短保持时间和冷却，避免一秒一个主意。
2. **片段层**：每次活动由可中断的步骤组成。例：玩具 `Orient → Stalk → Chase → Pounce → Recover`；食物 `Notice → Assess → Approach → Pause/Sniff → Eat/Leave`。片段的分支取决于状态和真实环境，不依赖固定概率硬抽。随机扰动使用已有存档种子，保证重播和离线结果一致。
3. **运动层**：地面移动由一个位置权威驱动：路径系统给方向和目标速度，动画只表现步态；不让路径、动画根运动和物理同时改角色位置。动画步幅与真实位移相配，支撑脚接地，启动、急停和转向分别处理。跳跃作为离散动作：预备／起跳 → 腾空 → 着陆 → 回稳；只有预先标注的安全起落点可触发。
4. **表现层**：头眼注视、耳朵、尾巴、呼吸、眨眼等作为有原因的叠加层。视线先于身体转动，扑击前有重心后移，落地后有整理动作。避免所有微动作按固定周期同步重复。
5. **离线与存档**：保存有语义的目标、需要、位置和片段结果；后台恢复时做有界的世界补算，不逐帧重演跳跃。短时动画以当前语义状态重建，避免重新进来时猫悬空或瞬移。

建议的代码边界：`MomoApp` 把“轻声呼唤”“放食物”“移动玩具”转成刺激事件；`Simulation` 返回可解释的结果（听见但继续休息、转头观察、靠近、后退等），由它决定是否设置路线；`ImportedCatView` 只把结果表演出来。替换 `Call(Point)` 时，别用旧的地板坐标作为“隐形召唤点”。新增持久状态应保留既有存档读取，并提供版本迁移；当前 `schema=1` 与固定长度冷却数组需要一起审查。

### 动画技术路线

- 当前 Legacy 混合足够展示八段原型动作，但要做走／小跑／短冲、转向、扑、跳和事件中断，建议把**一只**灰虎斑先迁到 Unity 的 Generic `Animator`，用状态过渡处理不同动作，用 Blend Tree 处理同类步态速度。Unity 官方说明 Blend Tree 适合混合相似、接触相位对齐的走和跑；不同动作靠状态过渡。[Unity：动画混合树](https://docs.unity3d.com/cn/6000.0/Manual/class-BlendTree.html)；[Unity：动画过渡](https://docs.unity3d.com/cn/current/Manual/class-Transition.html)
- 先做少而完整的关键片段：待机变化、起步／停步／转身、走／小跑／短冲、伏低／潜行／扑击／落地回稳、原地观察／嗅闻／进食、上跳／下跳／落地。坐卧、伸展、梳理沿用现有片段并返修接触动作。每段标注爪落地、事件触发和可中断窗口。
- 四足脚部的落点、头部注视及高处落地可逐步使用 Animation Rigging 约束修正；该包依赖 `Animator`，本项目当前尚未安装，因此迁移和手机性能都需单独验证。[Unity：Animation Rigging 包](https://docs.unity3d.com/kr/6000.0/Manual/com.unity.animation.rigging.html)；[Unity：Rigging 工作流](https://docs.unity3d.com/ja/Packages/com.unity.animation.rigging%401.2/manual/RiggingWorkflow.html)
- 高处移动不能只把角色 Y 坐标插值。先在房间加一处低台和一处可退回的高处，标注足够大的起落区域、朝向、障碍和镜头可见性；再加入带起落点的 2.5D 路径边。真实室内猫需要可用的立体空间，但游戏里的跳跃高度和频率应按模型、家具和镜头实测。[FelineVMA：猫的环境需求](https://catvets.com/wp-content/uploads/2026/02/FelineVMA-Environmental-Needs_2026-BW.pdf)
- 当前灰虎斑骨骼与三角网格能否支撑极端伸展和近景表情，需要先做 3 段试片：急转短跑、扑击落地、上跳下跳。若肩、髋、腹部变形或头脸表情不达标，应替换为有清晰商业使用条款的成熟四足角色／委托修模与动作；继续在现有网格上叠脚本无法修好形变。九只猫暂时复用一致的行为系统，资源升级先只验一只。

## 实施顺序与验收

| 阶段 | 交付 | 必须观察到的结果 |
| --- | --- | --- |
| 1. 取消“听令” | 地板轻点不导航；呼唤成为可拒绝的社交刺激；抚摸有距离和意愿门槛。保留原存档兼容。 | 睡眠、梳理、探索、低亲近和高亲近情境下，猫的反应不同，且屏幕提示和实际动作一致。 |
| 2. 食物闭环 | 放食物入口、观察／靠近／嗅闻／吃或离开；食物与需求状态、熟悉度关联。 | 熟悉食物可较快接近；新异或受惊会停顿；不饿可忽略；进食只在到达食物后发生。 |
| 3. 幼猫式游戏片段 | 一只猫的短冲、伏低、追逐、扑击、落地和恢复；主动发起游戏和玩后的休息。 | 十分钟无输入也有可理解的自发行为；玩家逗猫棒能看到完整捕猎式序列，且不会无休止跑动。 |
| 4. 立体空间 | 一处低台、一处可躲／可栖的高处，专用上下跳片段与落脚检测。 | 只在合理起落点跳，路径不穿家具；起跳、空中、落地、回稳连续。 |
| 5. 角色和真机门槛 | 一只猫的动作／变形审片、iPhone 长时性能与真实触摸体验。 | 实机观察脚滑、穿模、反应延迟、近景表情、温度与耗电；由目标用户判断它是否像“自己在生活”，而非通过编译或自动测试代替。 |

验证建议同时录三组固定场景：无输入自由活动、相同食物在不同安全感下的响应、同一玩具在不同能量下的响应。把当前版与试片版盲测对比，询问观察者“猫刚才为什么这么做”“下一步可能做什么”，再看他们能否从动作读出意图。技术回归覆盖存档、离线补算、路径和触摸隔离；主观生命感仍以视频与真机人眼评审为准。

## Kenney 隔离试片（2026-09-29）

`Assets/Momo/Scenes/CatBehaviorStudy.unity` 是独立场景，只构建到 `Builds/CatBehaviorStudy/MomoCatStudy.app`。它不初始化 Momo 的正式房间、不读取或写入宠物存档，也不修改现有灰虎斑资源。打开试片后按 `1` 到 `6`，或用底部按钮切换：忙碌时呼唤只注意、愿意亲近时靠近、陌生食物先观察并中途停顿、熟悉食物较快靠近、不饿时不靠近、一次自主短跑。开发版带 `--cat-behavior-review` 参数可自动重放六段并输出渲染帧与分支结果到 `artifacts/cat-behavior-study/`。

这些决策门槛和时长仅是**可观察的产品假设**，不是实猫行为数据。片段目前只有转身、走／跑、暂停和吃的现成动作；没有真正的嗅闻、扑击或跳跃，也没有环境安全感和关系史的长期记忆。**通过审片只证明资源能在 Unity 内运行，且六条原型分支按预期发生，不代表写实感已达标，也不代表正式主猫已改好。** 下一步应先请人看试片，确认“靠近前的停顿”和“拒绝响应”能被读懂，再把规则接入正式 `Simulation` 并补齐四足动作与场景高处。

**实际审片结果**：Unity 6000.3.23f1 macOS Development Player 构建成功；运行时识别了 `idle/walk/run/eat` 等 8 段 Kenney FBX 动画。六个场景均完成，时长分别约 1.8、4.0、13.7、8.3、1.8、3.2 秒；分支断言验证了是否移动、是否中途停顿、是否到食盆后进食。32 秒渲染录像在 `artifacts/cat-behavior-study/review.mp4`，依次为 0:00 忙碌呼唤、0:02 亲近呼唤、0:06 谨慎靠近食物、0:19 熟悉食物、0:27 不饿拒绝、0:29 自主短跑。完整结果见同目录 `PASS.txt`。镜头审片发现方块模型的面部与步态表达有限，暂停也缺少实际嗅闻；这正是下一步需要换四足动作资源、增加头颈与接地修正的原因。

重建命令使用 Unity Editor 的 `-executeMethod Momo.Editor.CatBehaviorStudyBuilder.BuildMac`；生成的 app 可直接打开，按数字键 `1`–`6` 切换情境。自动审片可运行 app 内的 `Contents/MacOS/Momo --cat-behavior-review`。该构建器只保存和构建独立场景，不修改默认场景列表。

## 动作复审与 V2（2026-10-09）

用户实际观察后的反馈是“动作不自然，硬邦邦的”。V1 的行为分支通过不能作为动作自然度的验收。复查发现：进入移动状态就使用恒定速度，到目标立即停下；呼唤时整体转身；动画独立循环，没有根据真实路程推进步幅；方块猫自身也缺少独立头颈、四足躯干和完整动作过渡。

V2 使用已有四足骨架的灰虎斑。现在用 `--cat-behavior-v2` 启动旧版：数字键 `1`–`6` 重放情境，`B` 切换 V1 方块猫和 V2 灰虎斑。改动包括：

- 用连续的速度曲线起步、巡航和减速，末端确实停下，避免恒速骤停和无限慢爬。
- 呼唤时先由头颈注视，愿意靠近后身体再转向；身体转向也有平滑的角速度。
- 由每帧真实位移推进四足步态相位，再混合待机与行走，停止位移后不继续空踩。
- 按灰虎斑身体长度设置食物和玩具的停靠距离；进食时用头颈接触修正，前肢重新求解以保持原接地点，避免前爪踩进食盆。该修正仅在试片的 `TickStudy` 路径中启用。
- V2 的玩具片段是快走到球旁、拍爪、恢复；当前模型没有真正的 Run 片段，不能把加速 Walk 当作完整跑步交付。

实际 Unity Development Player 重放了六段，验证分支、有限形变、起停和转向连续性。移动加速度峰值约 2.89 世界单位/秒²，转向峰值约 88.6°/秒；技术阈值只是捕捉突变的调参门槛。估计鼻尖距选定食物点仍约 0.153 世界单位，属于近似接触，不代表嘴部与食物已精确贴合。录像用固定 30 fps 逐帧记录并按相同帧率编码，共 1122 帧、37.4 秒：`artifacts/cat-behavior-study/v2/review.mp4`。运行结果和情境起始帧在同目录 `PASS.txt`、`timings.txt`；`python3 scripts/render-cat-behavior-study.py` 可重编码已完成的审片。

**仍未通过真人自然度验收**。当前灰虎斑的基础动作来自本地程序生成，肩胛、脊柱、髋部的动作表达有限，眼睑和口部形变缺失，也没有完整的跑、伏低、扑、跳与落地动作。平滑位移能纠正驱动问题，但这些缺口需要成熟四足动作资源或返修骨架与手工动画。资源候选应先审原始走跑、急转、起停、进食和跳落地视频，再接入工程。例如 [Indie Cat / Low Poly Cats](https://assetstore-fallback.unity.com/packages/3d/characters/animals/mammals/low-poly-cats-185996) 的作者页面列出 90 段动画、Walk/Run/Trot/Crouch/Jump 和站坐卧睡之间的过渡、59 根骨骼及形态键，比仅有循环的资源覆盖更完整；它是商店资产，当前没有购买、下载或验证，不能把作者描述当作 Momo 的效果证明。开源行为框架同样不能补齐这些动画。
