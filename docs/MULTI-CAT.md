# 多猫同住：实现与验收

本轮把房间从单猫扩展为最多五只独立的猫。用户在小店逐只领养；点击左上名字打开家庭名册，或直接点中屋里的猫切换关注。名册中再次点关注中的猫，可查看原有状态页。其他猫继续生活，小店打开时已领养的猫也继续推进。轻点空地只用于观察；「轻声唤它」依据距离、性格、需要和当前活动产生可拒绝的邀请。

## 状态与兼容

- `HouseholdState` 是 schema 2 根对象，保存共享时间、球、基础补给、猫列表、关注 ID 和有方向的猫间关系。
- `CatState` 保存稳定 ID、原有单猫 `WorldState` 生命数据、朝向、身体范围、社交冷却、模型选择和资源等待状态。原有 `Simulation` 继续负责每只猫的需要、性格、偏好、习惯和有界回忆，独立随机状态不会共用。
- `WorldState` 保留旧类名和 schema 1，以便原规则和旧档解码；它在家庭中是单猫生命数据，而不是新的家庭根对象。
- `HouseholdStore` 先读 `household-0/1.save`，完整性校验后选择最大 revision。只有没有家庭检查点时，才尝试读取并迁移原 `world-0/1.save`。原文件不写入；已有家庭检查点全部损坏时明确停止，不悄悄回退旧猫档。`.pending` 不参与恢复。
- 第一只猫的名字、性格、关系、习惯、回忆和外观选择保留。新增猫复制角色配置，不共享可变性格对象。五只上限在核心和入口同时检查。

## 移动与防穿模

`WorldSimulation` 每 0.1 世界秒推进一次前台移动，需求继续使用原五世界秒 tick；世界速度保持六倍。大帧分成相同的小步，不通过丢弃时间跳过碰撞。表现层在家庭模式下直接读取已提交的位置，步态由实际位移驱动，不再单独平滑切入家具。

`CatNavigation` 在原家具碰撞边界上扩大空间，提供对转身较保守的地面身体包围范围。每步扫过整个线段并检查其他猫的身体距离；朝向变化不会扩大这个圆形范围。先做局部侧让，无法前进时对动态身体重新寻路；窄口使用稳定时段的轮换优先级和退让。清醒、没有参与人或猫互动的猫，可在阻挡同伴时移开；不会为让路强行唤醒睡猫。

静态身体检测与动画接触是不同精度。本轮约束地面主体的包围范围，不等同于逐顶点的全皮肤碰撞证明；尾巴、胡须、极端动作仍需美术和接触点验证。没有把当前未制作的扑跳、蹭头或互相舔毛伪装成已经完成的互动。

人走动时避开所有猫，猫也避开观察者；人移动进原目标时会重新选可达位置，配对互动必要时取消。资源目标按活动占用释放，等待位置避开食盆的出入口。相邻食盆和水盆对目前保守身体范围只允许一只进入，其他猫在附近等待；实际到盆边才开始消耗食物或水，等待中不远程进食。红球在邀请和自主玩耍时有一个使用者，其他猫可观察。

## 猫之间的互动

前台短暂的 `InteractionSession` 包含双方、类型、阶段、站位与超时：邀请 → 对方评估 → 双方靠近 → 嗅闻／追逐／附近休息 → 完成或取消。

双方都要满足需要、活动、距离与可见条件。对方可拒绝；睡觉、吃喝、躲避、掌心喂食和其他独占互动有优先权。接受后预留双方位置，任何一方退出或急需照料时释放互动。只有真实完成后，才更新有方向的熟悉度／舒适度和带参与者 ID 的回忆。相互嗅闻使用现有注视和基础姿态；追逐使用受约束的短程移动，尚无专用跑扑动画。

互动会话、喂食动作和让路过程不恢复为半段动画；暂停先清理临时会话。离线按原有有界逻辑补算每只猫的生活，恢复时清理短时过程、重建安全地面位置，不逐帧重演社交或跳跃。补给仍自动保障，离开不会惩罚宠物。

## 代码入口

- `Assets/Momo/Core/HouseholdState.cs`、`HouseholdStore.cs`：家庭数据和旧档迁移。
- `Assets/Momo/Core/WorldSimulation.cs`：共享推进、资源、移动和社交协调。
- `Assets/Momo/Core/CatNavigation.cs`：身体范围、家具与动态邻居路径。
- `Assets/Momo/Runtime/MomoApp.cs`：多角色、手势目标锁定、领养、关注切换和生命周期。
- `Assets/Momo/Runtime/CatView.cs`、`ImportedCatView.cs`：家庭位置权威下的动作表现。
- `tests/MultiCatTests.cs`：迁移、碰撞、让行、资源、拒绝、中断、关系和长时间运行回归。
- `Assets/Momo/Runtime/MultiCatReview.cs`：`--multi-cat-review` 开发参数，在临时隔离存档中通过真实生产入口验证并保存画面。

## 验证入口与边界

完整本地回归入口为 `./scripts/check-multicat.sh`。单独运行核心检查使用 `./scripts/test-core.sh`，构建使用 `./scripts/build.sh mac`。使用构建后的 Player 加 `--multi-cat-review`，输出 `artifacts/multicat/PASS.txt` 或 `FAIL.txt`，以及手机／平板比例截图。Player 检查包含五次领养、实际 Collider 点选、名册布局、空地点按、迎面过门、相互嗅闻、共享食盆、Unity 存档往返及离线恢复。

核心与桌面 Player 通过，才能说明这套功能可运行。真实感仍需实际观看和试玩评审；iPhone 的触摸、持续帧率、发热和电量需要真机单独验收。完整蹭头、互舔、扑跳需要相应的配对动画、接触锚点和立体落点系统。

### 本轮结果（2026-10-22）

- 核心 65/65 项通过，包括 20 组不同起始条件的五猫生活、十分钟等效前台生活、观察者进入原目标、资源排队、睡眠保护和旧档完整性。
- 最终 macOS Development Player 离屏回归通过：390×844、320×700、768×1024 的五猫和名册画面，五只真实 Collider 点选、未关注猫与观察者避让、空地点按、窄门会车、嗅闻、单只使用食盆、Unity 家庭存档与六小时恢复。检查 1332 个场景步骤，身体包围范围最小间距 0.01502 世界单位，表现位置与逻辑位置误差为 0。证据为 `artifacts/multicat/PASS.txt` 及同目录 PNG。
- 最终原功能离屏回归通过：厨房、后院、掌心食物、真实口部接触、室内四口和室外进食、摸头、移动暂停／恢复、饱腹拒绝、状态反馈与面板取消。证据为 `artifacts/garden-feeding/PASS.txt`、`artifacts/multicat-garden-regression.log`。
- 原九猫小店的批处理回归通过：36 次预览与档案进出、实际 640×480 画布边界、领养保存、房间恢复及重新打开；该检查不宣称九猫小店的多分辨率截图。证据为 `artifacts/boutique/PASS.txt`。
- iPhone 0.3.0（11）导出及 Release / iphoneos 签名编译通过，`codesign --verify --deep --strict` 通过。已更新到连接的实体 iPhone 并成功启动；证据为 `artifacts/multicat-iphone-install.log`、`multicat-iphone-launch.log`。

离屏画面由开发检查专用 RenderTexture 和屏幕空间相机 UI 产生；普通运行仍使用原来的屏幕覆盖 UI。离屏循环帧时间不作为显示帧率或手机性能证据。仍待真人评审自然度，以及真机连续触控、30 分钟性能、发热与电量验收。
