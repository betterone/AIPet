# 创造我的猫：功能规划（暂存）

状态：规划暂存，尚未实现。本板块暂缓，当前优先改善现有猫的互动、趣味性和关系感。后续启动创作板块时，以本文为讨论与实现基线。

## 目标与当前基础

用户亲手决定猫的样子，预先认识它的初始性格，再把它带回家。首版以可互动的 3D 猫定制为主；照片或文字辅助创作留作后续入口。

当前工程已有名字、三种毛色和三种初始性格。角色由基础几何体构成；完整花纹、异瞳和体型变化需要扩展角色表现层。外观与行为需要共享一套稳定的角色结构。

## 创作流程

选择起点 → 定制外观 → 初识性格 → 命名 → 带它回家。

1. 从示例猫开始，或随机遇见一只；示例不是锁定模板，外观仍可修改。
2. 在同一只 3D 猫上实时调整外观，支持旋转、近看。
3. 选择初始性格，观察相应的短互动反应。
4. 输入名字，预览完整猫咪档案。
5. 点击“带它回家”，成功保存后进入房间并留下第一条相遇回忆。

体验目标：2–3 分钟能完成，也允许继续细调。该时间为设计目标，尚待使用者验证。

## 外观范围

| 分类 | 建议首版内容 |
| --- | --- |
| 底色 | 奶油、白、灰、黑、橘、棕等协调色板 |
| 花纹 | 纯色、虎斑、双色、三花 |
| 局部特征 | 白胸口、白手套、脸部色块；允许左右不对称 |
| 眼睛 | 琥珀、绿、蓝，可选异瞳 |
| 脸型 | 圆润到修长的小范围调整 |
| 体态 | 纤细、适中、圆润三个安全档位 |
| 尾巴 | 长短与弯曲程度的小范围选择 |

优先实现白手套、异瞳和脸部斑块等辨识特征。体态变化必须满足动作与碰撞约束。长毛、特殊骨架和大量服装留待后续。

## 性格与互动预览

- 活泼：注意到球后更快靠近、试探。
- 温柔：更容易回应伸手，停留片刻。
- 独立：先观察，再决定是否靠近。

这些预览必须由实际行为参数驱动。初始性格不是最终关系；玩具偏好、玩耍时段和熟悉程度仍由相处形成。不得通过外观直接推定性格。

## 手机界面

全屏创作页，上半屏约六成显示猫咪，下半屏显示分类和选项，底部固定上一步/下一步/带它回家按钮。

- 拖动旋转猫咪，双击回正面。
- 修改眼睛、脸部时自动拉近镜头。
- 一次展开一个外观分类。
- 撤销上一步，或恢复当前分类。
- 随机外观时可锁定已经喜欢的部分。
- 自动保存草稿，中途退出可继续。
- 预览时保持呼吸、眨眼与轻微动作。

## 存档与现有玩家

- 创作草稿与正式宠物分开保存。正式提交失败时保留草稿并允许重试。
- 预览与房间共用外观数据和渲染逻辑，避免进入房间后变样。
- 设置增加“编辑我的猫”，修改外观和名字时保留关系、习惯与回忆。
- 已存在的三种毛色显式迁移到对应外观配置，不重置旧宠物。存档版本升级需实现并验证迁移与回退。
- 外观随机种子与行为随机种子分开，修改外观不改变生活行为序列。
- 本板块继续采用单猫范围，不自动扩展为多猫管理。

## 分阶段交付

第一轮：实时外观预览、底色与基础花纹、眼睛与白色局部特征、初始性格、命名、草稿恢复、带回家、旧猫编辑。

第二轮：脸型体态细调、尾巴调整、更细的可重复生成斑纹、锁定局部随机、相遇纪念卡、照片辅助创作。按首轮动作和性能结果调整可选项。

照片入口建议先提取毛色和可见特征，映射到现有可编辑 3D 猫；看不到的部位由用户补选。任意照片直接生成完整可运动 3D 猫属于独立技术验证，不作为已承诺能力。

## 验收标准

1. 用户能做出明显不同且容易辨认的猫。
2. 编辑器预览、房间、重启后的外观一致。
3. 所有支持的组合能走、坐、睡、吃、玩，无明显穿模或碰撞错误。
4. 草稿退出后可恢复；正式创建不会因重复提交生成重复宠物或相遇记录。
5. 编辑外观不丢失关系、习惯、位置与回忆。
6. 旧存档升级后保留原有身份，异常时保留原始数据。
7. 手机端操作可用、文字清晰，预览性能经模拟器与真机分别验证。
