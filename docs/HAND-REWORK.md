# 连续手部模型替换

2026-10-23。

用户指出上一轮的手过假。重新审视后确认，原手掌、指节、腕部和前臂由球体、胶囊、圆柱拼接。此前的颜色、粗细与入画位置调整没有解决造型问题，不能视为手部美术完成。

## 本轮改变

- 移除拼接手和圆柱袖口，换为连续的手掌、指缝、手腕与前臂蒙皮。
- 使用 para 在 OpenGameArt 发布、标注 CC0 的手臂资产，其原始网格和皮肤贴图来自 MakeHuman。作者页面：https://opengameart.org/content/fps-arms-rigged-only 。来源、许可与修改记录保存在 `Assets/Momo/Resources/CompanionHand/SOURCE.txt`。
- 去掉原 FPS 控制器、IK 约束、上臂及动画；保留一侧手与前臂，另一侧镜像。细分一次改善轮廓，保留 1024px 皮肤 UV 贴图；每只约 7313 个顶点、7284 个四边面（导入后约 1.46 万三角形），23 骨骼、每顶点最多 4 权重。
- 15 个手指关节分段弯曲，托粮手略微合拢；抓粮、翻掌和收回沿用原喂食阶段。左手姿态根据前臂接近方向调整，减少腕部急弯。
- 粮粒按新掌心比例缩小。手掌交互碰撞范围随模型缩小，掌心世界坐标、猫站位、实际口部接触、食物收益和拒绝规则沿用原逻辑。
- 未购买资产、接入在线服务或改动真实宠物存档。

## 实际复核

最终 macOS Player 的喂食回归覆盖：粮袋点击、抓粮翻掌、拖动右手、猫实际口部接触、四口进食、喂食同时摸头、移动暂停及恢复、饱腹拒绝、后院喂食和打开面板取消。390 与 320 宽检查画面来自隔离临时存档。结果见 `artifacts/hand-rework/player.log` 和 `artifacts/garden-feeding/PASS.txt`。

`artifacts/hand-rework/before/` 保存旧版实际截图；`after/` 保存本轮最终截图。对比图为实际截图拼版，没有修绘场景像素。抓粮和翻掌的额外阶段截图也由原 Player 回归入口捕获。

代码入口：`CompanionHands` 协调现有语义状态、位置与食物；`CompanionHandView` 驱动蒙皮手指与前臂。`CompanionHandImporter` 设置 Generic 导入、关闭原动画并配置手机 ASTC 贴图。`scripts/model-tools/prepare_hands.py [解压后的资源目录]` 可复现模型处理，需要本地 bpy 4.5.3。

## 仍需验收

这是对旧拼接手的模型替换，不代表已达到写实手部或动作成品。抓粮路线、翻掌时机、指腹接触、关节极端变形、快速拖手和腕部扭转仍需真人连续观看。原猫的嘴部、咀嚼及抚摸反馈动画的缺口仍在。

本轮未更新 iPhone，未验证新增蒙皮的真机持续性能和触控观感。桌面流程通过不能代替真实手感和自然度评审。

## 第二次纠正：左右手、拇指与臂长

用户再次指出“手还是很假，而且大拇指方向也不对”。上一轮换网格不能作为自然度通过，旧截图和旧结论保留作历史。

发现的结构问题：运行时用负缩放反射骨骼，所有指节沿同一世界轴旋转，拇指没有独立对掌动作；前臂允许拉到原长 6 倍。即使喂食流程通过，也无法据此判断手部方向或自然度正确。

本次处理：

- 模型包含上臂和前臂，导入约 8173 顶点、8152 四边面、25 骨骼。源文件移到 Models，运行时只加载单独烘焙的 Right / Left prefab。
- 反射在编辑阶段写入网格位置、法线、三角绕序与绑定矩阵；运行时骨骼全部为正单位缩放。Bake 时检查：掌心向上、手指向前的标准坐标中，右拇指在内侧 -X，左拇指在内侧 +X。
- 每个指节拥有自己的局部弯曲轴；拇指 CMC 单独做对掌旋转，其余拇指关节独立屈曲，不再套用普通手指同轴规则。
- 使用腕—肘—肩两段固定长度求解，前臂约 0.39067、上臂约 0.37900 世界单位。取消非均匀拉伸，肘部向玩家一侧弯曲。
- 新增 `--hand-anatomy-review`，使用生产 prefab 与生产姿态驱动，输出左右手掌心、托粮、抓握、手背检查图。它使用独立临时存档，不修改真实宠物。

最终 macOS 构建、UNITY_IOS 源码编译、左右手校准及完整喂食回归通过。校准检查正单位缩放、拇指位置和手臂长度误差小于 0.0001；喂食回归同时检查这些约束。证据位于 `artifacts/hand-anatomy/`，汇总图为 `review.png`。

结论限于方向与骨骼结构纠正。当前皮肤资源的细节、腕部接触和程序姿态仍有粗糙感，不能宣称“已经自然”或“成品手部”。本轮仍未更新 iPhone。
