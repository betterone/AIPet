# 掌心喂食：转身、口鼻接近与手猫避碰

2026-10-26。针对用户指出的手猫穿模、猫背对着掌心吃粮，改为转身靠近、低头接近实际食物位置后才允许进食。此前流程通过不能证明接触正确，本轮增加逐口断言和逐帧接触检查。

## 原因与修改

- 家庭朝向曾每帧覆盖喂食转身；导入猫与原始猫都改为喂食关注优先，拿粮期间保持朝向食物。普通行走和结束后的自主行为继续由家庭模拟管理。
- 原判断在非 Eat 阶段跳过嘴部距离，Eat 阶段又容忍 0.45 世界单位；现在每一口都要求面对食物（水平朝向点积大于 0.9）、口鼻标记距离食物小于 0.075、手部接触代理重叠不超过 0.004，并到达合法站位。
- 在归一化后的实际模型表面校准口鼻与头顶标记。站位从最终渲染的食物位置计算，不再从避碰前的虚拟掌心计算；结合家具净空和观察者身体距离选择接近角度。
- 逼近终点收紧至 0.035，小幅拖手超过 0.025 即更新目标；喂食时使用 1.05 的照料站位净空，原有 1.03 身体避碰和其他猫避让继续生效，普通场景的 1.2 预留距离保留。
- 掌心喂食使用 Idle 加颈部目标求解，取消地面食盆 Eat 动画的干扰；口鼻从上方低头接近掌心。求解保留头部朝向，并保持前爪接地点。
- 手指、掌心、前臂有独立接触形状；猫的头部与身体使用从表面采样得到的凸代理。托粮时由猫避让稳定的手，抚摸手从头顶表面接近并向外解重叠。吃粮时头部接触修正上限 0.065，其余过渡阶段为 0.12；这是程序化接触约束，不是生理解剖范围结论。
- 托粮改为适度弯指，拇指向外舒展，抓粮时仍对掌。保留用户指定的左右源模型映射；人类手腕限制、固定臂长和正缩放继续检查。
- 动作结束先在掌边停留，再收手和恢复站姿；取消会穿入手掌的蹭手接触。截屏等待帧仍继续解接触，避免检查时动画已更新而手部避碰遗漏。

## 验证与证据

- 67 项核心测试通过，包含精确到达掌心、缺少嘴部接触不能吃粮、小幅拖手重新靠近，以及近距离照料仍保留观察者身体净空。
- macOS 构建与 WindowViewChecks 通过；UNITY_IOS 源码编译通过，0 错误、0 警告。
- 实际 Player 的粮袋点击、拖手、室内四口完整进食、同时摸头、移动暂停恢复、户外进食、拒绝和取消检查通过；每次增加吃粮次数都复核朝向、口鼻距离和手部接触状态。
- 五种导入外观及原始卡通外观，分别确认新一轮抓粮从零口开始，再实际完成首口及 48 帧同时摸头检查。接触代理最大重叠约 0.00035–0.00298 世界单位，小于 0.006 阈值。原始卡通猫的物理接触改用头部／身体网格代理，避免将扩大点击区域用于近距离接触。
- 最终代码录制 540 帧、固定 1/30 秒步进的 18 秒连续画面，覆盖抓粮、翻掌、转身、低头、四口进食、摸头、收手和站姿恢复；逐帧接触代理最大重叠 0.002757907（Sniff 阶段）。这不是设备帧率测试。

## 边界

接触代理是模型表面的近似，逐帧阈值为 0.006；不等同于每个皮肤三角形、胡须和毛发都没有交叠。嘴部标记来自表面校准并跟随骨骼，也不是嘴唇逐顶点测量。现有资产没有完整的下颌、舌头和唇形动画，四口反馈仍是程序化口鼻动作与粮粒减少；不能称为 CS 级角色动画成品。

本轮没有更新 iPhone，也没有真机触控、帧率、发热或用户自然度验收。
