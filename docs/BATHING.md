# 后院洗澡

更新：2026-10-29。第一人称、手动、分步照料；每次一只猫，其他猫继续生活。

同日后续 [界面精简](QUIET-HUD.md) 将洗澡卡压缩为 108 逻辑点高，完成步骤后才显示换工具，退出改为右上关闭图标。下文操作顺序不变；后续回归次数与画面以最新 `PASS.txt` 为准。

## 操作

后院中央偏西有地面入口浴盆，中心为世界坐标 `(0, 16.8)`。走到约 2.8 米内，点击洗澡盘，选择「叫它来洗澡」。也可以从「一起玩 → 后院洗澡」获得位置提示；这个入口只转动视线，不传送玩家或猫。

猫先观察，镜头稍向后让出入口，再让猫自行走入。困倦、正在吃喝、饥渴、躲避、参与其他独占互动或暂时不愿靠近时会拒绝。洗澡盘被占用、入口附近有猫，或 30 真实秒内未能到达，也会结束邀请。

到位后入口挡板升起，水逐渐加到躯干中部；猫的根位置仍在地面，水面没有碰撞体。镜头靠近，移动盘和普通环视暂时停用。依次完成：

1. **打湿**：按住花洒，在身体上慢慢移动。
2. **搓泡泡**：完成打湿后点「换上沐浴露」，自动拿起海绵、按泵取液并交到右手，再沿毛发滑动。
3. **冲净**：换回花洒，冲掉各处的泡沫。
4. **擦干**：排水、降下入口挡板后换毛巾，轻轻滑动擦干；全部完成后猫自行走出。

每步完成时把同一件工具放回挂座／托盘，空手收回，镜头稍拉开，可以看清猫和浴盆，再换下一件工具。中断会清空临时水与泡泡、打开入口，不留下一个封闭的浴盆。

背部、左右身体各分成四个覆盖片区。花洒每片需约 1 秒，搓洗和擦干每片需约 1.5 秒有效接触，完整操作约一至两分钟，观察和换工具另计。不会因按住一个位置而洗完整只猫。镜头在松手时缓慢调整到未完成片区；头脸不计入清洗目标。普通喂食双手和洗浴双手共用现有手部模型与固定臂长求解规则。

连续两秒对准头脸或过快操作会暂停；松手两秒后恢复，第三次不适则结束。超过 90 秒没有触碰或整次超过五分钟也会结束。速度、时间与覆盖规则均为首版产品参数，不是现实养猫建议。

## 脏污与反馈

每只猫的 `WorldState.dirt` 独立保存，0 为干净，100 为最脏。前台在后院实际移动或玩耍时，每真实分钟增加 2 点；室内、静止和离线不增加。清洁描述放在状态页，不占常驻需求条，不增加健康、关系或离线惩罚。

完整洗完才将脏污归零。起始脏污至少 20 时记录一次洗澡回忆；干净的猫也能洗，但不会刷回忆或亲密值。洗澡中的湿润、泡沫和暂时洗掉的灰尘都是表现层效果，中断后恢复未完成前的脏污。

猫的材质参数由逐角色 `MaterialPropertyBlock` 设置，不修改共享外观资源。当前反应包含站姿、转头和小幅避水姿态，保留脚底站位；这些是在现有基础动作上增加的有限反应，不代表完成了高精度湿毛、真实擦毛形变或完整专业洗浴动画。

## 水与泡沫（2026-10-29）

- 浴盆有地面高度的防滑盆底、排水口、三面侧壁和可降下的透明入口挡板。猫仍沿核心导航走入，绕开盆壁；观察者绕整个浴盆行走。旧存档先按原规则读取，再由家庭位置整理移出新盆壁。
- `BathWaterView` 使用 28×34 分段网格，叠加轻微波动和最多八个传播、衰减的涟漪源。花洒／搓洗会扰动水面，带出小水滴；静置也有轻微呼吸／站姿波纹。透明水面保留盆底与腿部可见性，水线下毛色带轻微水色。
- `BathBubbleField` 将大小不同的真实球面聚成不规则团簇：240 个身体附着位与 24 个漂浮位共用一个动态网格和一份薄膜材质。细泡更乳白，大泡更透明，带边缘反光、双高光与轻微薄膜色彩。搓洗产生少量飘起的泡泡，冲洗让泡团缩散、落到水面，游离泡最终破裂淡去。
- 附着点来自实际模型表面，并随骨骼权重更新；原始程序猫则绑定实际躯干网格。仅初始化时烘焙一次，逐帧只计算选定表面点。导入模型保持可读，以读取顶点和权重；这增加 CPU 模型内存，需在实体手机体验中关注。
- 表面取样显式使用 `BakeMesh(mesh, true)`，补偿渲染器缩放，再变换一次到世界坐标，避免泡泡悬空。[Unity API](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/skinnedmeshrenderer/bakemesh)
- 移除原来的白色表面泡沫着色，不用整层白色覆盖冒充泡泡。水波、浮力和薄膜是有数量上限的游戏表现，并非完整流体求解或真实湿毛模拟。

## 工具、拿取与出水（2026-10-29 第二轮）

- 入口右侧有固定在盆沿的侧托盘：泵瓶直立摆放，花洒在前侧挂座，海绵在前侧托盘，毛巾挂在前缘。工具在存放与使用时是同一组对象。托盘同时进入猫和观察者的避让范围；保留旧存档读取，再整理新家具附近的位置。
- 换工具自动执行伸手、拿取、按泵、交接、靠近、放回和收手，不增加按钮。拿取以实际手部挂接点到工具位置的距离确认；按泵使用食指末节位置，海绵由左手接液。工具转向随动作过渡。
- 花洒有握柄、开关、喷孔、挂座和持续连接的弯曲软管。握持时偏在接触点一侧，便于看到落水；喷头可作有限角度调整。右手持工具，左手只在搓洗／擦干时辅助，交接后会收回。
- `BathSpray` 的九条细水束按重力轨迹采样，并在实际猫身接触体、盆壁、盆底或水面处截断。移开猫身仍然出水，但不增加清洗覆盖；关水留少量余滴。水面冲击带出涟漪，毛发表面有短距离流水和下落水珠。水束碰到头脸会进入原来的提醒／暂停机制。
- 起泡先由实际接触点附近触发，再受对应身体片区进度约束；冲洗先减少接触处泡沫，脱落泡泡沿身侧向下运动。水面泡泡在排水时随水位下降并向排水口移动。
- 海绵接触时整体压缩，表面孔洞一起变化。`BathCloth` 使用 99 个顶点的布面，按局部接触体弯曲，限制并平滑变形，保留布纹与边条；擦干过程中毛巾中央逐渐变深，表示吸水。
- 动作和特效按前台真实时间推进，未引入持久化字段。拿工具时不计清洗进度；设置、后台和切猫会清理手势、取液、水滴，并把工具归位。再次邀请会立即使用当前观察者位置，避免把退出照料前的旧位置误判为挡住入口。

这些是有预算上限的游戏表现：软管为曲线，毛巾为局部贴合网格，水束与泡泡用接触体近似。没有声称完成软体／液体的完整物理求解。

## 系统与存档

- `BathSession` 负责邀请、阶段、覆盖、暂停、完成与取消；按真实秒推进，与六倍世界时间分开。
- `WorldSimulation` 负责猫的移动、洗浴位置预留、多猫避让，以及只在前台增长脏污。需求继续推进，洗澡期间暂停该猫自主选择活动。
- `BathController` 处理实际触摸、角色接触体射线、手与工具、镜头和中断；`CatBathEffects` 处理逐角色湿润、灰尘和泡沫。
- 新字段缺失时默认干净；保留家庭 schema 2、单猫 schema 1 和原活动枚举。洗澡会话不进入 JSON，重开不继续半段洗澡。
- 自动保存时只在序列化快照中清理洗澡猫的临时接近路线，正在运行的猫仍正常走入；存档不会恢复一段失去会话的洗澡路线。
- 设置、切猫、逗猫棒、喂食、进入小店、退到窗外、后台与退出均释放洗澡状态。中断不提交清洁结果，也不回滚正常推进的猫咪需求。

## 验证

统一入口：`./scripts/check-bathing.sh`。它运行同源核心测试、`UNITY_IOS` 源码编译、macOS Player 构建、实际洗澡操作、原喂食和五猫生活回归。

开发参数 `--bath-review` 使用独立临时家庭档，不读取或覆盖真实宠物存档。结果输出在 `artifacts/bathing/`，只有完整检查通过才生成 `PASS.txt`；失败写入 `FAIL.txt`。截图通过开发用渲染目标生成，不是 iPhone 录屏。

验证结果以该目录的标记和构建日志为准。实体 iPhone 的连续触控、猫和手的自然度、镜头舒适度、帧率与发热需要另行体验；iPhone 的覆盖更新另记在对应版本文档中；桌面回归不代表真机触控与性能验收。
