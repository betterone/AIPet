# Momo WebGL / EdgeOne 输出说明

本页定义的是可分享的网页原型，不把它表述为与 iOS 版本完全相同的发行版。Unity WebGL 输出是静态文件；EdgeOne Pages 负责 HTTPS、缓存和分发，不需要为猫的本地生活常驻服务器。

## 构建

在 Unity Hub 给固定编辑器 `6000.3.23f1` 安装同版本 **WebGL Build Support** 后执行：

```sh
./scripts/build.sh webgl
```

产物位于 `Builds/WebGL`。本机当前只安装了 iOS Build Support；因此本次没有伪造 WebGL 构建成功的结果。安装模块后，应先在本地 HTTP 服务下打开 `Builds/WebGL/index.html`，不能直接双击 HTML 文件。

## 输入约定

| 行为 | 桌面浏览器 | 触屏浏览器 |
| --- | --- | --- |
| 在房间行走 | `WASD` 或方向键 | 左下摇杆 |
| 查看房间 | 鼠标右键或中键拖动 | 单指拖动 |
| 缩放 | 鼠标滚轮 | 双指捏合 |
| 抚摸、喂食、球与逗猫棒 | 鼠标左键点按／拖动 | 点按／拖动 |
| 打开／关闭菜单 | `Esc` | 菜单按钮 |

左键拖动的原有兼容路径仍保留；桌面端优先使用右键／中键看向，可避免把看向动作误识别为抚摸或点物品。WebGL 画布会拦截右键菜单。手机陀螺仪看向可在后续单独接入并要求用户授权；iOS ARKit 的“真实走近”不进入第一版网页，统一用摇杆或键盘行走。

网页小店首版主推 2026-11-09 新增的两只导入模型：英短蓝猫和三花；其余品种保留展示，但统一标为「待选」，不能从网页领养。iOS 小店隐藏这两只；若已有存档使用它们，宠物身份、关系和行为不变，只回退为原有程序化外观。

网页端的「试玩记录」和「拍照」会下载到浏览器，而不是显示沙盒目录。家庭存档仍使用 Unity WebGL 的持久化目录；浏览器清理站点数据、无痕模式或存储空间不足可能导致数据丢失，所以在上线前必须完成刷新、重开、浏览器关闭和存储配额的实际测试，并保留导出恢复方案。

## EdgeOne Pages 发布

1. 本地生成 `Builds/WebGL` 后，上传该目录或 Zip 到 EdgeOne Pages；也可使用 CLI：`edgeone pages deploy Builds/WebGL -n momo-webgl`。
2. 将首页设为 `index.html`，先使用预览地址验证 Chrome、Safari 和移动浏览器。
3. 对带内容哈希的 `Build/*` 文件使用长缓存；`index.html` 使用短缓存或不缓存，避免新版本 HTML 指向旧文件。
4. 确认 `.wasm` 返回 `application/wasm`，并实际验证 Brotli/Gzip 压缩产物能由站点正确交付。
5. 首次上线先将目标定为桌面 Chrome/Safari；手机网页仅在加载时间、内存、触屏与音频首次交互全部验收后公开支持。

没有账号、跨设备同步、排行榜或云端存档的需求时，不需要后端。以后若加入这些能力，再把鉴权和数据写入放到 Pages Functions/KV 或独立服务，不能让静态 WebGL 包直接持有密钥。

## 发布前验收

- 冷启动与二次加载；首包体积、压缩和缓存命中。
- 键盘对角移动、按键松开停止、鼠标右键拖动、滚轮边界、触屏摇杆和捏合。
- 左键互动不会被右键看向误触；浏览器右键菜单不遮挡画布。
- 本地存档的刷新、关闭重开、异常空间不足和导出试玩记录。
- Chrome、Safari，以及至少一台目标手机的帧率、内存、发热和音频授权。
