# Momo 视觉规范与成品门槛

更新：2026-10-23。

## 当前判断

当前是具备完整互动入口的可运行原型，尚不能按成熟游戏的视觉成品验收。本轮以正式场景、正式 HUD 和现有角色做统一调整，不以概念图替代运行效果。后续新增房间、玩法和角色都应遵守下述规范。

改前依据：`artifacts/visual-quality/before/` 保存的是此前实际桌面 Player 截图，不是同一轮、同一状态的严格 A/B。可观察问题包括图标与百分比叠压、浅色小字、墙地面黄偏色、旧房与扩建区材质割裂，以及近距离双手过粗、遮挡猫。

## 视觉方向

“湖蓝玩具家园”：安静的木地板、柔和的绿与蓝、少量珊瑚色可互动物品。保留猫耳门廊这个识别元素。最新小店实际渲染确认九只猫混用圆润程序化卡通与较写实导入模型，轮廓、眼睛、胡须、毛发纹理差异明显；这是当前整体协调性的主要阻碍。

猫和人猫接触的位置是第一视觉焦点；家具、装饰和 UI 为它服务。没有把低多边形场景与生成猫模型之间的风格差距视为已经解决。

### 色彩与材质

| 用途 | 色值 | 使用规则 |
| --- | --- | --- |
| 墙面 / 陶瓷 | #E8E5D5 / #F3F2E8 | 大面积低饱和，避免灯光再叠加强黄色 |
| 木 / 地板 | #C49C72 / #D8C7A9 | 所有房间共享材质角色，不按房间随意新增木色 |
| 湖蓝 / 布料薄荷 | #619AA8 / #BED3C8 | 沙发、袖口、软垫和门使用同一家族 |
| 草地 / 深叶 | #91B58B / #56866D | 后院与玩耍区统一，保持猫轮廓可读 |
| 珊瑚 / 蜂蜜 | #D28A72 / #D9BA76 | 屋檐、小物与门廊，避免铺满整个视野 |
| UI 主字 / 次字 | #243F40 / #526965 | 主字清楚、次字可读，禁止用低透明灰表现正文 |
| UI 底 / 主操作 | #F8FBF7 / #34796F | 面板稳定遮住背景；主操作用深青色 |

环境保持哑光，家具用真实小倒角。皮肤与袖口降低反光；不通过全局调色掩盖角色贴图和网格缺陷。日间使用接近中性的单方向光、冷暖平衡的三色环境光和接地软阴影；夜间降低主光，UI 保持相同可读性。小店延续房间木色和布料色。

### 界面与排版

- 字体统一使用内嵌 MomoUi（中英同一字体资产）；标题 23、主要行操作 16、正文 14、辅助文字目标 12 个逻辑点。空间受限的非操作元数据可保留 10–11，但不得承载关键操作指引。
- 场景常驻控制以 390×844 为参考，适配 320、390、430 宽手机和 768 宽平板。位置基于安全区域，不以截图像素硬推真机安全区。
- 面板内边距约 20–24，行间隔 10–12；同级面板共享圆角、阴影、遮罩和关闭按钮样式。
- 房间可操作按钮至少 44×44 逻辑点。小店的屏幕投影名字牌目前仍小于此门槛，需要与 3D 猫的实际点击区域共同复核，不计为整款游戏触控全部达标。
- 正文与底色、主按钮文字与底色对比度至少 4.5:1。这是本项目采用的可读性门槛，不代表存在一个覆盖所有游戏的统一认证。
- 饱腹与亲密各有独立状态卡：左图标、右数值和标签。图标不能作为数字背景；反馈浮字只在实际收益时出现。
- 喂食提示位于顶部，收粮按钮与状态卡错层；隐藏次要回正按钮。猫头与掌心应尽量留在画面中部，不让文字盖住互动。
- 功能、操作和拒绝提示使用简短中文；开发检查与诊断只在开发模式出现。

### 角色、动作与镜头的成品要求

以下是必须继续完成的门槛，不能以本轮配色调整判定通过：

1. 逐只检查九猫与导入灰虎斑的比例、贴图清晰度、毛色与环境风格；近景不能出现明显生成残片、材质接缝或不合理高光。
2. 走、停、转身、睡眠、进食、抚摸、追逐在身体重量与接触上连续；补齐眼睑、嘴部及缺少的跑扑等动作资源，再由真人审片。
3. 掌心接触、抚摸触点、腕部与前臂连接应自然，双手不能交叉遮住主要猫脸；本轮只减细前臂和调整材质，尚不等于手部解剖与动画成品验收。
4. 普通游玩镜头、找猫、递手、五猫和窄房间都应保持焦点可读；不能只凭专门摆拍的全景判断完成。
5. iPhone 上检查刘海与底部安全区、触控、中文清晰度、明暗变化，以及连续 30 分钟帧率、发热和电量。桌面批处理帧时间不能充当实机性能。

## 本轮复核入口

```sh
./scripts/build.sh mac
Builds/macOS/Momo.app/Contents/MacOS/Momo -batchmode --visual-quality-review -screen-width 390 -screen-height 844 -logFile artifacts/visual-quality/player.log
Builds/macOS/Momo.app/Contents/MacOS/Momo -batchmode --garden-feeding-review -screen-width 390 -screen-height 844 -logFile artifacts/visual-quality/feeding.log
Builds/macOS/Momo.app/Contents/MacOS/Momo -batchmode --multi-cat-review -screen-width 390 -screen-height 844 -logFile artifacts/visual-quality/multicat.log
```

视觉复核入口使用独立临时存档。`after/` 保存实际游戏渲染，`PASS.txt` 仅表示所列的技术检查通过，不代表真人审美、真机或发布验收。现有喂食、多猫与小店回归单独记录，不把历史结果挪作本轮结果。

## 本轮实际结果

- 65 项同源核心检查通过；桌面和 UNITY_IOS 源码编译通过，macOS Development Player 构建通过。
- 最终视觉复核通过：320×700、390×844、430×932、768×1024 的房间和六类面板；检查内嵌字体、截字、越界、房间按钮最小逻辑尺寸、状态图标与数字分离，以及指定文字配色的对比度。
- 最终掌心喂食与多猫 Player 回归通过。截图复查后，将收粮按钮移回顶部状态卡旁；左前臂从侧面入画，双臂起点调整以减轻近镜头的透视放大，手掌与猫的接触规则沿用原逻辑。
- 普通桌面窗口的小店四种尺寸、36 次九猫预览、档案、领养与返回流程均通过。对应结果见 `artifacts/visual-quality/boutique.log` 与 `artifacts/boutique/PASS.txt`。
- 实际渲染汇总：`artifacts/visual-quality/overview.png`。前后截图的场景数据、镜头可能不同，不用作严格数值 A/B。截图没有修绘场景像素。
- 本轮更新本地源代码与 macOS 成品，没有更新 iPhone 安装包。尚未进行本轮真机触控、性能或人眼自然度验收，也未上传发布。

结论：界面和环境已完成一轮可验证的规范统一；角色风格混用、近景资产质量、配对与捕猎动作、手部造型及真机体验仍是成品验收的开放项。
